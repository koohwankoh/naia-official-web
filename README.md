# NAIA 공식 웹사이트 v3.1 — 게시 승인 흐름

## 게시글 절차
1. CMS 편집기에서 작성한 글을 **임시저장**하면 상태가 `작성중`으로 저장됩니다.
2. **승인 요청**을 누르면 `승인요청` 상태가 되고, 공개 홈페이지 메뉴에는 노출되지 않습니다.
3. 관리자는 **관리자 페이지 → 메뉴별 게시글·카탈로그 DB** 목록에서 제목을 열어 내용을 확인한 뒤 `승인`을 누릅니다.
4. 승인 후 상태는 `승인완료`가 됩니다. 이때 목록의 **관리자 수정**으로 내용을 편집하고 **승인 후 수정 저장**을 누릅니다.
5. 다시 목록으로 돌아와 **발행**을 누르면 `발행완료` 상태가 되어 홈페이지에 게시됩니다.
6. 공개 메뉴의 글을 눌러 상세 본문을 확인합니다. 발행된 글을 수정하면 다시 `승인요청`으로 돌아가 재검토를 거칩니다.

목록에는 작성중, 승인요청, 승인완료, 발행완료 상태가 함께 표시됩니다. 승인요청과 승인완료 글에만 해당 단계의 액션이 나타나고, 홈페이지 카탈로그는 발행완료 글만 렌더링합니다. 게시글 HTML은 저장 전에 허용 태그/속성만 남기도록 정리합니다.

## 파일 및 배포
- `index.html`: 랜딩 페이지와 관리자 페이지가 함께 포함된 단일 페이지 앱
- `admin.html`: 같은 페이지 파일을 관리자 진입용으로 제공
- `assets/`: 로고, 프로필, 조직도 이미지
- `.github/workflows/deploy.yml`: main 브랜치 push 시 GitHub Pages 배포
- `CNAME`: www.naia.kr 도메인 설정

압축 해제 후 파일과 폴더를 저장소 최상위에 올리고 커밋합니다. ZIP 파일 자체만 올리면 사이트가 게시되지 않습니다. Actions 탭에서 배포 성공을 확인하고 Settings → Pages에서 Pages 연결 상태를 확인하세요.

## 데이터 저장의 한계
승인 상태와 게시글은 현재 브라우저 `localStorage`에 저장됩니다. 따라서 승인 작성자와 관리자가 서로 다른 기기/브라우저를 쓰면 요청이 공유되지 않습니다. GitHub Pages는 정적 호스팅이라 DB 서버 기능을 제공하지 않습니다. 조직 내 실제 승인 운영에는 인증을 갖춘 공용 DB/API 백엔드 연동이 필요합니다. 현 버전은 동일 브라우저 내 승인 흐름 검토용입니다.

첨부 원본의 임시 로그인 정보는 실제 인증으로 사용할 수 없습니다. 공개 저장소에 그대로 배포하지 말고 인증/DB를 서버에서 처리하도록 교체해야 합니다.
